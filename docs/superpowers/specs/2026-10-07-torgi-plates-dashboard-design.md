# Торги: источники в навигации, номерные знаки, дашборд, избранное

Дата: 2026-10-07
Статус: согласовано

## Задача

Бэкенд торгов (`torgi.mos.ru`, транспорт) уже собирает лоты в `torgi_lots` с
историей версий, отдаёт `/torgi/lots`, `/torgi/lots/{id}/versions`,
`/torgi/stats`, `/torgi/file` и обновляется джобой. На фронте торгов нет вовсе.

Нужно:

1. развести два источника в навигации: `mosres` (москварталы, квартиры и дома) и
   «Торги» (транспорт), текущие страницы уезжают внутрь первой группы;
2. разобраться с номерными знаками: нормализовать, распарсить, дать пользователю
   задавать паттерны и получать уведомление на сайте при попадании;
3. дашборд по торгам с графиками;
4. избранное по лотам;
5. обновлять данные торгов чаще.

Версионирование и схема хранения остаются теми же, что у квартир и корпусов:
основная таблица + `*_history` + `*_temp`, история пишется триггером при разнице
в сравниваемых колонках.

## 1. Навигация

Сайдбар (`frontend/src/components/AppShell.tsx`) получает две группы с
заголовками. Существующие роуты не меняются, новые живут под `/torgi`.

```
mosres                      ТОРГИ
  Сводка        /             Сводка торгов  /torgi
  Квартиры      /aparts       Машины         /torgi/cars
  Дома          /buildings     Лот           /torgi/cars/:lot_id
  Карта         /map          Номера         /torgi/plates
  Ипотека       /mortgage
Уведомления     /notifications   (общий колокольчик, две вкладки внутри)
```

Решение: группы, а не переключатель источника — нет нового состояния, которое
надо синхронизировать с URL, и нет редиректов со старых ссылок.

## 2. Номерные знаки: нормализация и разбор

`plate` приходит из карточки лота сырой строкой (`"А001АА77"`, иногда с
пробелами, латинскими гомоглифами, иногда мусор вроде «отсутствует»).

Новый модуль `src/plates.py`:

* `HOMOGLYPHS` — карта латиница→кириллица для `A B E K M H O P C T Y X`;
* `normalize_plate(raw) -> str | None` — upper, подстановка гомоглифов, выкидываем
  всё кроме букв и цифр, пустое → `None`;
* `parse_plate(raw) -> PlateParts` — `plate_norm`, `plate_region`, `plate_valid`.

Разбираемые форматы (буквы только из `АВЕКМНОРСТУХ`, регион 2–3 цифры):

| формат | шаблон | пример |
|---|---|---|
| легковой | буква + 3 цифры + 2 буквы + регион | `А001АА77` |
| такси / общественный | 2 буквы + 3 цифры + регион | `АА12377` |
| прицеп | 2 буквы + 4 цифры + регион | `АА123477` |
| мото | 4 цифры + 2 буквы + регион | `1234АА77` |

Ни один не подошёл — `plate_valid = false`, `plate_norm` всё равно сохраняем,
`plate_region = NULL`.

Три новые колонки в `TorgiLotMixing` (`src/mixins.py`) — значит и в
`torgi_lots`, и в `torgi_lots_history`, и в `torgi_lots_temp`:

| колонка | тип | зачем |
|---|---|---|
| `plate_norm` | text | матчинг паттернов, поиск |
| `plate_region` | text | фильтр и гистограмма регионов |
| `plate_valid` | bool | отделить мусор от разобранного номера |

Колонки считаются при загрузке в `src/torgi.py` (там, где уже собирается строка
лота), не выражением в SQL: один источник правды, и история хранит ровно то, что
видел портал в тот прогон.

Список сравниваемых колонок триггера в `src/pg_definitions.py` пополняется теми
же тремя именами — иначе история их не увидит. Первый прогон после миграции
поднимет версию у всех лотов один раз: это ожидаемое следствие, не баг.

## 3. Язык маски номера

Подстановочные символы — неалфавитные, поэтому любая буква или цифра в маске
всегда означает саму себя.

| символ | значение |
|---|---|
| `?` | любая буква из `АВЕКМНОРСТУХ` |
| `#` | любая цифра |
| `=` | повтор предыдущего символа |
| `*` | любой остаток строки |
| буква или цифра | буквально (латиница нормализуется в кириллицу) |

```
?###??*     формат легкового, любой номер
?#==??*     три одинаковые цифры
?777??*     номер с 777
*77         любой номер 77 региона
?###МР*     серия **МР
А001АА77    точный номер
```

`mask_to_regex(mask) -> str` компилирует в анкеренный Postgres-regex; `=`
превращает предыдущий атом в группу и ставит backreference (`(\d)\1`).
Валидация: длина ≤ 12, только разрешённые символы, `=` не первым символом,
`*` допустим. Невалидная маска — HTTP 422 с текстом ошибки.

### Пресеты

Часть полезных правил маской не выражается: «зеркальные» (121) требуют ссылки
на символ двумя позициями раньше, а `=` ссылается только на предыдущий. Поэтому
пресеты — отдельный каталог готовых regex в `src/plates.py`
(`PRESETS: dict[label, regex]`): три одинаковые цифры, зеркальные, блатные серии
(АМР, ЕКХ, ММР, АОО), номер по региону, малые цифры 001–009. Пресет сохраняется
как watch с `mask = NULL` и готовым `regex`; язык маски из-за него не растёт.

## 4. Паттерны и уведомления

```sql
plate_watches(
  id serial pk,
  user_id  int not null references users(id) on delete cascade,
  mask     text null,            -- NULL = пресет
  regex    text not null,
  label    text null,
  created_at timestamp default now(),
  unique (user_id, regex)
)
```

Эндпоинты:

* `GET /torgi/watches` — список паттернов пользователя с `matched_now`;
* `POST /torgi/watches` — `{mask}` либо `{preset}` + необязательный `label`;
  в ответе `matched_now` — сколько лотов в базе уже подходит, то есть сохранение
  работает и предпросмотром;
* `DELETE /torgi/watches/{id}` — только свой паттерн (иначе 404).

`GET /torgi/notifications?days=N` — одна лента, причина в поле `kind`:

* `plate_match` — лот с подходящим номером появился, или у существующего лота
  номер появился/изменился. Берётся первая версия в `torgi_lots_history`, где
  `plate_norm` матчится паттерном, и только если она попадает в окно `days`;
* `lot_change` — по избранным лотам: упала начальная цена, сменился статус,
  появилась итоговая цена.

Матчинг делается в SQL (`plate_norm ~ w.regex`), таблицы «уже отправленного»
нет: добавил паттерн — сразу видно и прошлые попадания. Непрочитанное считает
существующий `useNotifSeen` (`lastSeen` в localStorage); колокольчик в сайдбаре
суммирует обе ленты, `NotificationsPage` получает две вкладки
(Квартиры / Торги) на существующем `ui/tabs`.

`src/sql/torgi_lots.sql` дополняется полем `matched_masks` (массив подошедших
масок/лейблов через `LEFT JOIN LATERAL` по `plate_watches` текущего
пользователя) и фильтром `watch_only`, плюс фильтрами `plate_region` и
`valid_plate_only`. Это даёт значок «под твой паттерн» в самой таблице.

## 5. Избранное по лотам

```sql
torgi_favorites(
  lot_id  int references torgi_lots(lot_id) on delete cascade,
  user_id int references users(id)          on delete cascade,
  primary key (lot_id, user_id)
)
```

Отдельная таблица, а не полиморфный `favorites`: ноль миграции существующих
данных, целостность остаётся на FK. Эндпоинты `/torgi/favorites` GET/POST/DELETE
повторяют `/favorites`. В `torgi_lots.sql` появляются `is_favorite` и фильтр
`fav_only`; `user_id` берётся из ContextVar `current_user_id()`, как в квартирах.

## 6. Дашборд торгов

Два запроса, не семь.

`GET /torgi/dashboard` — один payload:

* KPI-плитки: лотов всего, в приёме заявок, продано, средняя начальная цена,
  медианный Δ итог/начало, лотов под мои паттерны;
* разбивка по категориям транспорта (существующий `torgi_stats.sql`);
* топ марок;
* воронка статусов;
* динамика по месяцам `tender_date`: лотов, сумма итоговых, средний дисконт;
* ближайшие дедлайны приёма заявок;
* лента изменений из `torgi_lots_history`.

`GET /torgi/points` — тонкий массив
(`lot_id, brand, year, mileage, start_price, final_price, category, is_open,
plate_region, latitude, longitude`), на нём три виджета: scatter пробег/цена,
карта лотов (react-leaflet уже в зависимостях), гистограмма регионов номеров.
Без фото и длинных текстов — payload остаётся маленьким.

Новые файлы в `src/sql/`: `torgi_dashboard.sql`, `torgi_brands.sql`,
`torgi_timeseries.sql`, `torgi_funnel.sql`, `torgi_changes.sql`,
`torgi_deadlines.sql`, `torgi_points.sql`, `torgi_notifications.sql`.

## 7. Страницы торгов

`/torgi/cars` — таблица на `@tanstack/react-table` по образцу `ApartsTable`:
все колонки доступны через существующий `ColumnsMenu`, тулбар с фильтрами
(статус, категория, марка, год, цена, пробег, регион номера, только с номером,
только избранные, только под мои паттерны, поиск по названию/марке/модели/
номеру/VIN), выгрузка в Excel на `/torgi/file`.

`/torgi/cars/:lot_id` — все данные лота: галерея фото, видео, VIN, ПТС, цвет,
кузов, эко-класс, мощность, объём двигателя, привод, КПП, пробег, задаток, шаг
аукциона, координаты, просмотры портала, разобранный номер (норма, регион,
валидность), ссылки на ЭТП / torgi.gov / портал, звезда избранного, график
начальной цены по версиям и таблица версий на `/torgi/lots/{id}/versions`.

`/torgi/plates` — список паттернов, конструктор маски с подсказкой по символам и
кнопками пресетов, счётчик текущих совпадений, переход в таблицу с
`watch_only=1`.

`EXPORT_COLUMNS` в `src/torgi.py` дополняется до полного набора полей (цвет,
кузов, эко-класс, регион номера).

## 8. Частота обновления

`TORGI_REFRESH_INTERVAL_MINUTES`: 180 → 15 (`src/config.py`, `.env.example`,
README). Список — ~16 запросов по 100 лотов, карточки по-прежнему тянутся только
для лотов с изменившимся `updateDate`, поэтому в стабильном режиме прогон почти
бесплатный. На сводке торгов — кнопка «обновить сейчас» на существующий
`/torgi/update_data`.

## 9. Миграция

Одна ревизия Alembic: три колонки в `torgi_lots`, `torgi_lots_history`,
`torgi_lots_temp`; таблицы `plate_watches` и `torgi_favorites`; пересоздание
функции-триггера истории с новым списком колонок; индексы
`plate_watches(user_id)`, `torgi_lots(plate_norm)`, `torgi_lots(plate_region)`.

## 10. Проверки

`tests/test_plates.py` (новый):

* нормализация: латинские гомоглифы, пробелы и регистр, мусорная строка, пустое;
* парс четырёх форматов + неразбираемый номер (`plate_valid = false`);
* `mask_to_regex` на каждом символе языка (`?`, `#`, `=`, `*`, литералы) и
  отказ на кривой маске (`=` первым, запрещённый символ, перебор длины);
* каждый пресет компилируется и ловит свой эталонный номер.

`tests/test_torgi.py` (расширяем): избранное лота, попадание паттерна в
`/torgi/lots` (`matched_masks`, `watch_only`) и в `/torgi/notifications`,
форма payload `/torgi/dashboard` и `/torgi/points`, запись `plate_norm` /
`plate_region` / `plate_valid` при загрузке лота.
